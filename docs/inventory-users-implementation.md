Reviewed the supplied request against catalog/inventory forms and services, invoice/POS item selectors, server Supabase clients, current owner/admin/editor/viewer roles, RLS helpers, native accounting cutover/stock posting, secure image storage, dependencies and Vercel configuration. Confirmed source: catalog_items retains PRODUCT/SERVICE, integer stock, exact PostgreSQL numeric prices and existing invoice/transaction UUID links. Current catalog upserts directly edit quantity and deletes remove items. Native active tenants require Python source/ledger transactions. Memberships have no deactivation flag; helpers and runtime authorization must be updated together. Locations/categories/teams/tax-rate persistence is absent. The implementation will use additive fields/tables and authenticated, versioned, retry-safe mutations; retain existing quantity/price/accounting/document records; map legacy text categories without rewriting old item values; archive instead of deleting; introduce active membership checks at all application/storage/accounting entrypoints; and expose real directory/team/Auth-event/audit usage data. New tax selection is limited to supported no-tax catalog metadata until an actual tax configuration and reviewed posting path exist. Existing manual invoice tax behavior is preserved. Integer stock quantities remain the existing contract; unit labels do not introduce fractional stock or a new costing policy.

This branch starts from reviewed main, independently of the unmerged AI feature drafts. No production migration, activation, provider email or deployment is performed during implementation. Final validation, migration sequence, compatibility and rollback steps will be recorded here.

## Delivered flows

- Catalog and Inventory share the existing component/service architecture. Products and Services have separate categories, bounded server pagination, name/code/category search, status/category filters and tracked-product low-stock filtering. Add forms start with type/name/category/code/price and expand optional details. Owner/Admin can view/edit/archive/reactivate; Editor can create; Viewer can read. Images use the existing private, validated PNG/JPG upload pipeline after the item is saved.
- New item codes are generated when blank, editable and checked against every item in the business. Existing duplicate/missing codes remain unchanged; unchanged legacy numeric precision is retained. New/changed NGN money fields require nonnegative exact two-decimal values. Legacy text categories use a separate association map so renames/archive preserve their items without rewriting original catalog rows.
- Item versions detect concurrent edits. Creation/stock changes carry a stable request key; confirmed validation failures can be corrected, while an unconfirmed response freezes the original payload for safe retry, including closing/reopening its dialog. Existing quantities cannot be edited in the item form. Reasoned adjustments cannot make stock negative. History snapshots and document references remain unchanged. Referenced type/unit/tracking changes are rejected.
- Native stock uses the existing restricted Python transaction and library journals: positive opening stock debits inventory and credits reviewed equity; quantity corrections offset inventory against the reviewed COGS mapping. Source item, movement, stock event, journal, audit and replay result commit together. Missing mapping, invalid cutover date, closed/missing period or posting failure rolls everything back. Existing on-hand cost cannot be silently revalued. Legacy tenants retain their existing cash-basis/derived-inventory behavior and receive an audited stock movement rather than a second financial ledger.
- User Management shows saved users/invitations, role/status/location filters, tenant-local display names, versioned edits, deactivate/reactivate, pending invitations, real teams/membership management, recorded Supabase Auth events and application audit activity. Activity count means audit records, including material item events and management events; it is not billable usage or a unique-operation count. Last activity is computed from stored event timestamps.
- Admin cannot modify an Owner or grant Owner. Last active Owner protection includes deactivation. Deactivation retains the membership, Auth user, historical references and audit trail. Application selection/context, PostgreSQL RLS helpers, native membership/collection locks, low-stock notification recipients and private upload authorization all check current active membership. In-flight accounting writes serialize against the same business lock; later tenant requests fail even with an older valid JWT.

## Using the features

Open Catalog or Inventory, choose Products/Services, then Add. Choose Uncategorized for a quick item; a manager can create/select a category directly in the form. Expand Additional details when needed. Save before attaching an image through View. Use View for the recorded metadata, Edit for current details, Archive/Reactivate for availability and Adjust stock for a dated quantity correction with a reason. If a response is unconfirmed, retry the original request rather than creating another item.

Open Settings > Users. Search/filter saved accounts, edit a tenant-local name/role/location, or deactivate/reactivate after confirmation. Use Invite user and Copy link while delivery is disabled. Create locations under Branches and locations. Create teams and add/remove existing business members by email. Sign-ins and Usage show actual captured records and honest empty states.

## Compatibility and rollback

Before migration commit, any SQL failure rolls back all changes. After commit, retain additive columns/tables, category associations, stock movements, invitations and audit records: never drop/reset them to roll back application code. Prefer a forward fix. If a release must be withdrawn, freeze catalog/user writes or expose them read-only while keeping active-membership authorization and stock-tracking compatibility patches in both backend and frontend. Do not restore broad browser DML grants, the old quantity RPC or an old native fulfillment implementation that treats untracked products as tracked. An old UI is not safe to redeploy with write controls against this schema. Reverse any posted stock correction only through a new authorized, reasoned adjustment with its own key and reviewed accounting date; never remove its journal/history.
